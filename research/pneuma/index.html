Undergraduate thesis

PNEUMA — Video Memory for Long-Form Question Answering

A training-free system that converts long video into structured, queryable memory across relational, vector, and temporal stores.

North South UniversityFour-person teamSupervisor: Dr. Nabeel Mohammed

Status: completed undergraduate thesis. The research direction was discontinued after evaluation and engineering audits exposed unresolved evidence-grounding and correctness limitations.

Thesis motivation

One event should remain retrievable through several attributes

A long video can contain a single moment that is relevant as an action, an object, a place, a spoken phrase, or a temporal neighbor. PNEUMA explored whether frozen perception models could populate a persistent memory that supports several retrieval paths instead of reducing every moment to one embedding.

The resulting system segmented video into overlapping chunks, coordinated frozen action, vision-language, speech, and embedding models, and stored structured records in SQLite, five aspect-specific FAISS indices, and a temporal NetworkX graph. A custom executor decomposed questions, selected a retrieval plan, disambiguated candidates, and synthesized an answer with source chunks and confidence.

Architecture

A hybrid memory with explicit planning

Structured ingestion

Three-second chunks with one-second overlap combine action/keyframe signals, vision-language descriptions, transcripts, and normalized semantic fields.

Tri-store memory

Normalized SQL supports exact filters, five FAISS spaces support aspect-specific similarity, and a temporal graph represents ordering and time relations.

Plan-selecting executor

The system chooses SQL-first, FAISS-first, graph-first, hybrid, or recent-first retrieval, then verifies and synthesizes the evidence.

Benchmark harness

EgoSchema, NExT-QA, and MovieChat-1K drivers isolate memory per video and evaluate generated answers with a retrieval-aware external judge and uncertainty statistics.

Evaluation and audit

The harness existed; the final accuracy evidence did not

The public description separates implemented evaluation machinery from unavailable aggregate outcomes.

Role and provenance

Team contribution without invented module ownership

Team project
PNEUMA was completed by a four-person undergraduate thesis team. The available archive does not establish file-level individual authorship, so this page describes project-level architecture rather than assigning modules to Tanvir.
Project-built
Chunk orchestration, structured parsers, normalization, hybrid memory, query planning, benchmark drivers, product API, and the line-referenced engineering audit.
External / frozen
V-JEPA 2, InternVL 3.5, Whisper, CLIP, Qwen3-VL, and the public long-video QA benchmarks.
Not performed
No model training or fine-tuning. No verified cross-video temporal reasoning, completed real-time stream, or traceable final benchmark accuracy.

What carried forward

From system ambition to stricter retrieval questions

PNEUMA left useful questions even though the research line stopped: what should a memory retain, how should evidence be structured, and how should retrieval be evaluated without mistaking an answer-producing pipeline for a validated memory system?

Those questions motivate the later ERL work, which replaces architecture-first evaluation with paired interventions, matched budgets, registered gates, and explicit failure analysis.
