AirFLOW — Browser-Based Aerodynamic Analysis Workbench

A browser workbench for inspecting STL geometry, testing aerodynamic assumptions, and preparing an OpenFOAM case.

Early-stage collaborationBrowser MVPVLM and OpenFOAM preprocessing

Status: early-stage collaborative engineering developed with an aerospace practitioner and MIST graduate. The current browser workbench is a preliminary MVP; OpenFOAM case files were generated, but no solver run or CFD physics validation occurred. This wording does not imply official institutional sponsorship.

From raw geometry to explicit assumptions

AirFLOW treats a raw aircraft-like STL as uncertain geometry rather than a validated airframe. Axis mapping, units, mass assumptions, center of gravity, topology, and lifting-surface selection remain visible and editable before the numerical method runs.

The browser workbench then compiles manually selected surfaces into an idealized lifting surface, solves a standard horseshoe Vortex Lattice Method formulation through a custom implementation, derives longitudinal stability quantities, and prepares an OpenFOAM case using the same reference conventions.

Custom code around standard aerodynamic methods

Geometry and selection

Signed-tetrahedron mass properties, topology auditing, welded-edge adjacency, dual normal-angle flood selection, chord-envelope planform extraction, and a custom triangle BVH.

VLM and stability

Quarter-chord bound vortices, three-quarter-chord collocation, finite-segment Biot–Savart influence, partial-pivot solution diagnostics, Kutta–Joukowski forces, trim, and a linearized pitch demonstrator.

CFD handoff

A typed boundary manifest and generated blockMesh, snappyHexMesh, simpleFoam, k-ω SST, and forceCoeffs case files, plus a job API that refuses to report a run when solver binaries are absent.

External and standard

VLM, Biot–Savart, Kutta–Joukowski, ISA, Sutherland, flat-plate drag estimates, and RK4 are standard theory. Three.js is vendored; OpenFOAM is external; XFLR5 is reference-only.

Model limitations

The workbench does not report stall CLmax from an inviscid VLM, does not claim automatic surface recognition, does not present the unstable demo configuration as aircraft truth, and does not fabricate a CFD result when the external solver is unavailable.

Attribution and unresolved items

Collaboration context
The project receives technical input from an aerospace practitioner and MIST graduate; it is not presented as an official Bangladesh Air Force or MIST program.
Repository ownership
The audited repository is associated with Tanvir's GitHub identity and implements the full browser workbench without importing XFLR5 application code.
Assistance boundary
The CFD extension exists in an uncommitted working-tree record and the documentation suggests agent-assisted tooling. This page therefore avoids “solely hand-written” language.
License caution
The demo STL has uncertain provenance and should not be redistributed as a validated or authored asset. It is not copied into this website.
Open question
A real OpenFOAM run, mesh-quality audit, and controlled VLM-to-CFD comparison remain necessary before any CFD validation claim.
